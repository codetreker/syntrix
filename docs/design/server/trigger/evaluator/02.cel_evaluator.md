# CEL Evaluator

## Matching

The evaluator checks a rule's logical database, event type, and collection
before compiling or running its CEL condition. A database of `*` matches all
logical databases. Collection patterns use Go's `path.Match`; an invalid
pattern returns an error. An empty condition matches after these filters.

## Condition Input

CEL receives one dynamic `event` map:

```text
event.type       create | update | delete
event.timestamp  source event timestamp
event.document   current document fields, or null
event.before     before-image fields, or null
```

Document data fields are flattened into `event.document` or `event.before`.
The `id`, `collection`, and `version` system fields overwrite business fields
with those names. For example, `event.document.amount > 1000` evaluates a
business field when the current document is present. The current Puller
transformation does not populate a before image for ordinary changes; rules
that require one depend on the proposed [before-image capability](../../../../../.agents/notes/proposed/feature/2026-09-07-trigger-before-images.md).

## Compilation and Errors

The evaluator compiles nonempty conditions on first use and caches up to 1,000
programs by condition text, evicting the oldest entry when full. Rule loading
validates rule shape but does not compile its CEL expression. Syntax,
evaluation, and non-boolean result errors can therefore occur while processing
an event. They block that event and retry with cancellable backoff; the source
checkpoint cannot pass it. A permanently invalid condition requires a rule
correction or service cancellation before later source events can proceed.

See the [checkpoint contract](01.checkpoint.md) for progress ordering and the
[trigger rules reference](../../../../reference/trigger_rules.md) for rule
configuration.
