# Indexer gRPC Service

Date: January 10, 2026
Status: Draft
Scope: gRPC service interface for distributed deployments.

> For architecture overview, see [Indexer Architecture](01.architecture.md).
> For implementation details, see [Index Implementation](02.index.md).

## Overview

Indexer exposes a gRPC service for distributed deployments where Query Engine runs in a separate process. In standalone mode, Query Engine calls Indexer directly via the `LocalService` interface without gRPC overhead.

**Index Management**: Desired definitions come from configured templates; actual
state reports active concrete generations. Invalidation fences those generations
until maintenance bootstrap. Automatic reconciliation remains a separate
[proposal](../../../../.agents/notes/proposed/architecture/2026-09-07-indexer-recovery-lifecycle.md).

## Deployment Modes

| Mode | Indexer Location | Query Engine Calls |
|------|------------------|-------------------|
| Standalone | Same process as Query Engine | Direct `LocalService` interface call |
| Distributed | Separate process | gRPC `IndexerService` RPC |

## Declarative Management Model

The reconciliation diagram and diff rules below describe the proposed online
lifecycle. Production initialization and recovery use
[offline bootstrap](04.storage.md#offline-bootstrap-and-startup).

```

                     └────────┬────────┘

│  │  Desired State  │         │  Actual State   │            │
│  │  (from config)  │   vs    │  (in-memory)    │            │
│  └────────┬────────┘         └────────┬────────┘            │
│           │                           │                      │
│           └───────────┬───────────────┘                      │
```

### Diff Calculation Rules

| Desired | Actual | Operation |
|---------|--------|-----------|
| Present | Absent | **Create** - Create index, trigger rebuild |
| Absent | Present | **Delete** - Remove index data |
| Present | Healthy | No action |
| Present | Failed | **Rebuild** - Rebuild index |
| Present | Rebuilding | Wait for completion |

### Common Operations

| Scenario | Action |
|----------|--------|
| Change template definitions | Update configuration and perform maintenance bootstrap |
| Invalidate an index | Mark matching active concrete generations unavailable until maintenance bootstrap |
| View status | `GetState()` returns desired definitions and active concrete generation state |

### Active Generation Administration

`GetState.actual` uses concrete collection paths and the current template identity
for active generations. Obsolete generations are excluded. `DocCount = -1` means
unknown: administration does not scan postings to synthesize an expensive count.
This is independent of the aggregate service statistics below.

Invalidation requires a database and propagates storage errors. Broad pattern or
database requests affect only the finite existing partition inventory. An explicit
concrete collection can also invalidate a catalog-certified empty generation;
this does not require enumerating every possible wildcard collection. Affected
generations fail subsequent query admission. Invalidation does not itself launch
an online rebuild, and `Reload` does not yet implement full template reconciliation.

### Health Inventory

The existing `Health` call enumerates concrete query partitions and resolves their
current generations. Obsolete generation references are skipped. Each index key
is `database|concreteCollection|templateFingerprint|generation`, and every
`doc_count` is `-1` because document counts are not measured by this call.

| Generation state | Index state | Overall status effect |
|---|---|---|
| Ready with no failure | `healthy` | No degradation |
| Unpublished or not ready | `rebuilding` | Otherwise `ok` becomes `degraded` |
| Recorded failure | `failed` | `unhealthy` |

A stopped service, unapplied replay readiness, or lifecycle failure keeps overall
status `unhealthy`. Metadata-read failures and caller cancellation fail the health
call rather than returning a partial healthy inventory. This uses the existing
Health API and the same unknown-count convention as administration.

## Ordered Candidate Stream

Public Query pages use `OpenCandidates` in both local and distributed modes.
`Search` remains an internal single-result API; its raw OrderKey continuation does
not define the public page contract.

```text
CandidateRequest -> metadata -> complete group -> complete group -> completion
                       |              |
                 pinned plan      ID + K + branch IDs
```

| Message | Required information |
|---|---|
| Request | Database, concrete collection, typed filters, order, deletion visibility, after-position, template fingerprint, generation, branch hash, work budget |
| Metadata | Full template shape, fingerprint, generation, branch manifest, effective order, per-predicate access/residual assignments |
| Group | Logical document ID, complete common order position `K`, contributing branch IDs |
| Completion | Explicit end of traversal; EOF without completion is an error |
| Progress accounting | Cumulative examined entries, including entries skipped or suppressed by storage |

The request and each response are capped at 1 MiB. Metadata is sent exactly once
before groups. Groups strictly advance and contain every branch posting at their
position. All branches share one request-owned read view. Cancellation, transport
failure, malformed frames, or premature EOF close that view and fail the page;
clients never treat a truncated stream as successful exhaustion.

Filter values carry the [recursive typed codec](../../../reference/filters.md#typed-values),
preserving exact int64 and finite binary64. Predicate assignment preserves every
accepted condition; Query still rechecks the full conjunction and posting/position
proofs against authoritative documents. See
[Query coordination](../query/02.indexer-integration.md#filter-planning-and-page-coordination).

| gRPC status | Candidate failure reason |
|---|---|
| `InvalidArgument` | Invalid typed plan, unsupported field shape, or oversized branch/request manifest |
| `NotFound` | No complete access/order plan |
| `FailedPrecondition` | Stale template, generation, or branch continuation |
| `ResourceExhausted` | Candidate/view/response budget exceeded |
| `Unavailable` | Index not ready or rebuilding |
| `Canceled` / `DeadlineExceeded` | Request lifetime ended |
| `Internal` | Storage, codec, or execution failure |

Candidate errors carry `ErrorInfo` in the `syntrix.indexer` domain so clients retain
failure identity across gRPC. A stream's completion follows successful cleanup;
cleanup failure is observable.

```proto
syntax = "proto3";
package syntrix.indexer.v1;

option go_package = "github.com/syntrixbase/syntrix/api/gen/indexer/v1;indexerv1";

// Index management follows a declarative model:
// - Desired state comes from templates.yaml (loaded via Reload)
// - Actual state is the in-memory indexes
// - Reconciler computes diff and executes create/delete/rebuild operations
service IndexerService {
  // --- Query Interface ---

  // Search executes an index query and returns ordered document references.
  rpc Search(SearchRequest) returns (SearchResponse);

  // Public Query candidate stream; see Ordered Candidate Stream above.
  rpc OpenCandidates(CandidateRequest) returns (stream CandidateResponse);

  // Health returns the current health status of the indexer.
  rpc Health(HealthRequest) returns (HealthResponse);

  // Stats samples aggregate statistics for the current service instance.
  rpc Stats(StatsRequest) returns (StatsResponse);

  // --- Declarative Index Management ---

  // GetState returns the complete index state including desired, actual, and pending operations.
  rpc GetState(GetStateRequest) returns (IndexerState);

  // Reload reloads index templates from the configuration file (templates.yaml).
  rpc Reload(ReloadRequest) returns (ReloadResponse);

  // InvalidateIndex marks a index as needing rebuild.
  rpc InvalidateIndex(InvalidateIndexRequest) returns (InvalidateIndexResponse);
}

// --- Query Messages ---

message SearchRequest {
  string database = 1;
  string collection = 2;            // Concrete path: "users/alice/chats"
  repeated Filter filters = 3;      // Equality/range filters
  repeated OrderByField order_by = 4;
  int32 limit = 5;
  string start_after = 6;           // Base64 encoded cursor (OrderKey)
}

  string field = 1;
  string op = 2;                    // "eq", "gt", "lt", "gte", "lte"
  bytes value = 3;                  // JSON encoded value
}

message OrderByField {
  string field = 1;
  string direction = 2;             // "asc" or "desc"
}

message SearchResponse {
  repeated DocRef docs = 1;
}

message DocRef {
  string id = 1;
  string order_key = 2;             // Base64 encoded for cursor use
}

// --- Health Messages ---

message HealthRequest {}

message HealthResponse {
  string status = 1;                // "ok", "degraded", "unhealthy"
  map<string, IndexHealth> indexes = 2;
}

message IndexHealth {
  string state = 1;                 // "healthy", "rebuilding", "failed"
  int64 doc_count = 2;               // -1 when not measured
}

// --- Statistics Messages ---

message StatsRequest {}

message StatsResponse {
  int64 template_count = 1;
  int64 events_applied = 2;
  int64 last_event_time = 3;
}

// --- Declarative Index Management Messages ---

message GetStateRequest {
  string database = 1;              // Optional: filter by database
  string pattern = 2;               // Optional: filter by pattern
}

message IndexerState {
  repeated IndexSpec desired = 1;   // Desired indexes from configuration
  repeated IndexInfo actual = 2;    // Actual indexes in memory
  repeated PendingOperation pending_ops = 3;  // Pending reconcile operations
}

message IndexSpec {
  string pattern = 1;               // e.g., "users/*/chats"
  string template_id = 2;           // e.g., "timestamp:desc"
  repeated IndexField fields = 3;   // Indexed fields
}

message IndexField {
  string field = 1;

}
```

## Statistics

`Stats(ctx)` returns the same service-owned statistics in both deployment modes.
The remote adapter delegates to the local Service so that event statistics are
included alongside the Manager's template count. A successful zero result must
represent sampled state; transport or collection failures return errors.

```text
Local caller  -> Service.Stats -> Manager template count + Service event statistics
Remote caller -> Stats RPC    -> Service.Stats -> same statistics
```

The empty request selects the current Service instance, aggregated across all
databases. It has no database selector.

| Wire field | Go field | Meaning |
|---|---|---|
| `template_count` (`int64`) | `TemplateCount` (`int`) | Current loaded template count; distinct from instantiated index count |
| `events_applied` (`int64`) | `EventsApplied` (`int64`) | Number of events that complete matching-template processing |
| `last_event_time` (`int64`) | `LastEventTime` (`int64`) | Local Unix seconds recorded after the latest count update; zero before any event is counted |

| Event or lifecycle condition | Statistics behavior |
|---|---|
| Event returns before matching-template processing | Count and time unchanged |
| One event matches multiple templates | Count increases once |
| Individual template writes log errors | Processing continues and the event is still counted |
| Templates reload | Template count reflects loaded templates; event count and time remain |
| New Service instance | Event count and time start at zero |

The count does not prove successful index writes. The time is neither the source
event timestamp nor a checkpoint and cannot establish replication lag. A sample
alone cannot identify an instance restart.

Sampling uses existing in-memory state: a short read lock for template count and
separate atomic loads for event count and time. Reads are race-free, but the
three fields are not a joint atomic snapshot. No document or index scan, storage
request, or wait for catch-up is performed. Local sampling checks context before
and after the read; cancellation does not interrupt a mutex wait.

### Statistics Errors

| Condition | Result |
|---|---|
| Valid sample, including all zeros | Success |
| Request canceled | `Canceled` |
| Deadline expired | `DeadlineExceeded` |
| Service returns an existing gRPC status | Preserve its status code |
| Other collection error | `Internal` |
| Server unreachable | Transport error, including `Unavailable` |
| Server does not implement Stats | `Unimplemented` |
| Template count is negative or cannot fit the client's Go `int` | Client returns an invalid-response error |

The client forwards the caller's context and retains the error chain and gRPC
status while adding operation and endpoint context. It maps event count and time
without floating-point or unit conversion. The method requires no stored-data
migration; unsupported servers return an error without a zero-value fallback.

The [decision note](../../../../.agents/notes/implemented/feature/2026-09-07-indexer-remote-statistics.md)
records the alternatives and consequences. Lag, hit rate, and rebuild-duration
telemetry remain separate measurements.

## Service Interface (Go)

```go
// Service is the public interface for Indexer (both local and remote).
type Service interface {
    // Query - returns document references or error
    // Errors: ErrNoMatchingIndex, ErrIndexNotReady, ErrIndexRebuilding, ErrInvalidPlan
    Search(ctx context.Context, database string, plan Plan) ([]DocRef, error)
    Health(ctx context.Context) (Health, error)
    Stats(ctx context.Context) (Stats, error)
}

// LocalService extends Service with lifecycle and event handling methods.
// Only available for in-process usage.
type LocalService interface {
    Service

    // Start starts the indexer (loads templates, starts reconciler, subscribes to Puller).
    Start(ctx context.Context) error

    // Stop gracefully stops the indexer.
    Stop(ctx context.Context) error

    // ApplyEvent applies a change event to update indexes.
    ApplyEvent(ctx context.Context, evt *ChangeEvent) error

    // Manager returns the underlying index manager for advanced operations.
    Manager() *manager.Manager
}

// Indexer errors - returned from Search when index cannot serve the query
var (
    ErrNoMatchingIndex = errors.New("no matching index for query")
    ErrIndexNotReady   = errors.New("index not ready")
    ErrIndexRebuilding = errors.New("index is rebuilding")
    ErrInvalidPlan     = errors.New("invalid query plan")
)

// IndexerState contains the complete index state.
type IndexerState struct {
    Desired    []IndexSpec        // From configuration
    Actual     []IndexInfo        // In memory
    PendingOps []PendingOperation // Reconciler queue
}

// IndexSpec describes a desired index from configuration.
type IndexSpec struct {
    Pattern    string
    TemplateID string
    Fields     []IndexField
}

// IndexInfo describes an actual index in memory.
type IndexInfo struct {
    Database   string
    Pattern    string
    TemplateID string
    State      string  // "healthy", "rebuilding", "failed"
    DocCount   int64
}

// PendingOperation describes a reconciler operation.
type PendingOperation struct {
    OpType     string  // "create", "delete", "rebuild"
    Database   string
    Pattern    string
    TemplateID string
    Status     string  // "pending", "running"
    Progress   int     // 0-100
    Error      string
    StartedAt  time.Time
}

// ReloadResult contains the result of a reload operation.
type ReloadResult struct {
    TemplatesLoaded int
    Errors          []string
}
```

## Reconciler Logic

```go
func (r *Reconciler) Run(ctx context.Context) {
    ticker := time.NewTicker(5 * time.Second)
    for {
        select {
        case <-ctx.Done():
            return
        case <-ticker.C:
            r.reconcile()
        case <-r.triggerCh:  // Manual trigger (e.g., after Reload)
            r.reconcile()
        }
    }
}

func (r *Reconciler) reconcile() {
    desired := r.templateLoader.GetDesired()
    actual := r.manager.ListIndexes()

    ops := computeDiff(desired, actual)

    for _, op := range ops {
        switch op.Type {
        case OpCreate:
            r.createAndRebuild(op.Database, op.Pattern, op.TemplateID)
        case OpDelete:
            r.deleteIndex(op.Database, op.Pattern, op.TemplateID)
        case OpRebuild:
            r.rebuild(op.Database, op.Pattern, op.TemplateID)
        }
    }
}

func computeDiff(desired []IndexSpec, actual []IndexInfo) []Operation {
    var ops []Operation

    // Build lookup maps
    actualMap := make(map[string]IndexInfo)
    for _, a := range actual {
        key := fmt.Sprintf("%s|%s|%s", a.Database, a.Pattern, a.TemplateID)
        actualMap[key] = a
    }

    desiredSet := make(map[string]bool)
    for _, d := range desired {
        // For each database that has data matching this pattern
        for _, db := range r.getDatabasesWithPattern(d.Pattern) {
            key := fmt.Sprintf("%s|%s|%s", db, d.Pattern, d.TemplateID)
            desiredSet[key] = true

            if a, exists := actualMap[key]; !exists {
                ops = append(ops, Operation{Type: OpCreate, ...})
            } else if a.State == "failed" {
                ops = append(ops, Operation{Type: OpRebuild, ...})
            }
        }
    }

    // Find indexes to delete (in actual but not in desired)
    for key, a := range actualMap {
        if !desiredSet[key] {
            ops = append(ops, Operation{Type: OpDelete, ...})
        }
    }

    return ops
}
```

## Query Engine Integration

Query normalizes filters and cursor scope, opens the candidate stream, and
materializes ordered groups with explicit authoritative Store reads. Every result
passes scope, deletion, full-predicate, current-order, and current-posting checks.
Skipped candidates advance continuation and trigger refill until the requested
document count or exhaustion. Query owns final limits, the public cursor, and
page assembly; Indexer owns ordered candidates and their pinned read view.

The page envelope (`documents`, `nextCursor`, `effectiveOrder`) is carried through
local and gRPC Query services. Query gRPC requests and responses use wire version
2, with typed JSON bytes for filter values and complete document objects. Old
versions are rejected. Query gRPC pages are capped at 20 MiB, and the HTTP encoded
page remains capped at 16 MiB. The SDK reconstructs int64 as bigint.

The [HTTP contract](../../../reference/api.md#query-operations) owns response and
error shapes; [Index Storage](04.storage.md#offline-bootstrap-and-startup) owns the
complete-generation and replay-readiness requirement.

## Observability

The candidate gRPC adapter emits debug-level `Index candidates admitted` and
`Index candidates completed` records. Both carry the propagated `request_id`,
branch/plan hash, template fingerprint, hashed generation ID, and branch count.
Completion adds candidate-group count, examined entries, elapsed milliseconds,
and a sanitized termination reason. Pre-admission failures still produce a
completion record with no admitted identity.

`x-request-id` is preserved through Query and Indexer gRPC metadata. These logs
exclude predicate values, document contents, raw cursor positions, and error
messages. Local Query execution has its own
[completion diagnostics](../query/02.indexer-integration.md#request-observations).
Aggregate hit/miss/reconciliation metrics and OpenTelemetry tracing remain
separate instrumentation work; debug records do not claim those exporters.
