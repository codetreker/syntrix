# Managed Runtime Deployment Contract

**Status:** Proposed implementation design for PR 1; runtime code is unchanged.
**Baseline:** Runtime deployment commit `611a72046fabde827417a0ee2cf7522b46f0b4b9`,
with manual release delivery at `a10e779`.
**Purpose:** Make one Syntrix runtime bundle renderable, initializable, and observable
by operator tooling and the future Console instance controller through a
version-matched published package.

The [instance lifecycle design](03.instance_lifecycle.md) owns the five-PR sequence,
backend allocation, and Console authority. Its [decision note](../../../../.agents/notes/proposed/architecture/2026-10-12-console-instance-lifecycle.md)
owns alternatives and recovery consequences. This document specifies the runtime
prerequisite delivered by PR 1. PR 2 owns administrative resource/release policy
and allocates backends; PR 3 selects and executes published packages during
instance operations; PR 4 converges supported revisions; PR 5 supplies the interface.

## Problem and Existing Owners

The renderer, runtime modules, and provider already contain most required mechanisms.
Their current assembly does not establish the managed-instance contract:

| Existing owner | Current behavior and required change |
|---|---|
| [Renderer](../../../../packages/syntrix/internal/deployment/render.go), [model](../../../../packages/syntrix/internal/deployment/model.go), [values](../../../../packages/syntrix/internal/deployment/config/config.go) | Pure rendering uses supplied template bytes; expose a supported public API with embedded canonical templates. |
| [File adapter](../../../../packages/syntrix/internal/deployment/files.go) | Owns input/output paths and atomic private publication; keep those effects outside the reusable renderer. |
| [Release delivery](../../../../packages/syntrix/deployment/RELEASE.md) | Publishes tested images and matched CLI/template archives manually from main; add a compact managed-runtime contract marker and verify package capability output. |
| [Manager composition](../../../../packages/syntrix/internal/services/manager_init.go) | Drops configured broker storage, retry, durable-name, and channel options; compose one complete binding. |
| [NATS publisher](../../../../packages/syntrix/internal/core/pubsub/nats/publisher.go), [consumer](../../../../packages/syntrix/internal/core/pubsub/nats/consumer.go) | Both perform incomplete upserts; managed startup must only attach and verify. |
| [Storage assembly](../../../../packages/syntrix/internal/core/storage/factory_impl.go), [Identity module](../../../../packages/syntrix/internal/identity/runtime/module.go) | Own schema/repository construction; invoke every required owner-defined initializer without activating cleanup before acceptance. |
| [Subscription driver](../../../../packages/syntrix/internal/puller/core/subscription.go), [Puller protocol](../../../../packages/syntrix/api/proto/puller.proto) | Own registration, replay, and ready ordering; extend that path to acknowledge ordinary subscriptions. |
| [Process startup](../../../../packages/syntrix/internal/services/manager_start.go), [CLI](../../../../packages/syntrix/cmd/syntrix/main.go) | Some asynchronous failures are only logged; propagate terminal failure and expose actual enabled-role readiness. |

The [operator deployment guide](../../../../packages/syntrix/deployment/README.md)
already requires write/cleanup quiescence through normal indexed-query acceptance.
Its earlier bootstrap-success message and the corresponding CLI log permit an
earlier resume. PR 1 must make that ordering consistent.

## Delivery Boundary

PR 1 changes the runtime module, its Docker/CI/release inputs, protocols needed to observe
runtime readiness, and related documentation. It introduces no Console schema,
pool selection, credentials store, developer instance endpoint, reconciler, or UI.
The real Console module dependency is wired by its first consuming implementation.

Standalone retains local service calls and memory pubsub. Distributed retains
NATS and role-specific gRPC communication. Preserve existing state claims,
singleton restrictions, topology, bootstrap attestations, signing-key placement,
strict values loading, and credential-safe output behavior. Rendering supports
bootstrap, normal read-path acceptance, and full normal activation as explicit
phases; acceptance hold is not product Ready.

This is a deliberate configuration upgrade. Updated distributed values explicitly
declare broker authority and policy; missing required fields fail validation.
No legacy configuration decoder or existing-data migration is added. Operator
deployments remain supported with explicit values and existing maintenance rules.

## Public Renderer and Broker Specification

Move pure rendering/model code and tests to `packages/syntrix/deployment/`, and
values/configuration validation to its `config/` subpackage. Embed the two existing
`standalone/kubernetes.template.yml` and `distributed/kubernetes.template.yml`
files in place. Keep model types private and existing trusted template fields.

```go
// github.com/codetreker/syntrix/deployment
type Options struct {
    Bootstrap      bool
    WritesQuiesced bool
    AcceptanceOnly bool
}

func Render(c config.Config, options Options) ([]byte, error)
func RenderSource(source []byte, c config.Config, options Options) ([]byte, error)
```

Both entrypoints validate values/options, render to memory, validate every YAML
document, and return complete bytes or an error. `AcceptanceOnly` is normal-phase
only and mutually exclusive with `Bootstrap`; bootstrap itself always holds
internal writers. The acceptance option attests that external writers/cleanup stay
paused until finalization and full activation. They perform no filesystem,
database, Kubernetes, or broker operation. A successful result contains Secrets;
the caller owns protected storage and must not log it. Explicit-source templates
are trusted operator input, not a developer template-upload feature.

Move publication to `internal/deploymentcli`: retain `Generate`, `FileOptions`,
explicit `--template/--config/--output`, explicit stdout, input-alias rejection,
0600 temporary files, sync/close/rename, and failure cleanup. Its existing explicit
template CLI calls `RenderSource`. The published CLI and canonical templates come
from the same release. Console invokes that downloaded matching CLI; its own
compiled-in renderer must not interpret a different release's templates. Public
`Render` remains useful for runtime/operator callers compiled with that contract.

The public values owner composes a complete broker binding. Its pure specification
builder is shared by runtime attachment and future Console allocation:

```go
// github.com/codetreker/syntrix/deployment/config
type Ownership struct {
    InstallationID string
    InstanceID     string
    AllocationID   string
}

type BrokerBinding struct {
    ResourceMode  string // managed or operator
    SpecRevision  uint64
    Ownership     Ownership
    StreamName    string
    SubjectPrefix string
    ConsumerName  string
    Policy        BrokerPolicy
}

type BrokerPolicy struct {
    Storage     string // file or memory
    Replicas    int
    MaxBytes    int64
    MaxMessages int64
    MaxAge      time.Duration
}

type BrokerSpecification struct {
    Stream        jetstream.StreamConfig
    Consumer      jetstream.ConsumerConfig
    SubjectPrefix string
}

func (b BrokerBinding) Specification() (BrokerSpecification, error)
```

These types define the shared deployment-to-broker contract, not runtime service
defaults. Pubsub owns loading/validation of its runtime binding and provider
behavior; Trigger modules retain their worker/retry configuration. Root runtime
configuration only composes module types. Runtime consumers use the binding/spec
without depending on Kubernetes rendering or file publication. The already pinned
`nats.go v1.48.0` supplies the public SDK types; no dependency is added for PR 1.

The builder returns fresh slices/maps and rejects incomplete ownership, zero
revision, wildcard/invalid names, nonpositive limits/age, unsupported storage,
and replicas outside 1..5. Backend replication/metadata capability is additionally
validated during attachment. Instance/allocation identifiers are opaque 32 lowercase
hex IDs, matching existing generated IDs; installation IDs are nonempty printable
bounded identifiers, such as `console-development`, not UUIDs.

Managed names derive from the immutable instance ID:

```text
S = SYNTRIX_<32 lowercase instance-id hex>_TRIGGERS
stream = subject prefix = S
stream subjects = consumer filter = S.>
durable = S_DELIVERY
```

Operator bindings provide explicit stable ownership, names, revision, and policy
without Console records. Standalone requires no broker binding. Evaluator and
delivery derive the same binding; contradictory legacy stream/storage settings
fail validation. TaskPublisher supplies the existing unprefixed task subject;
pubsub prepends S once, including hashed long-subject fallback.

## Published Package and CLI Compatibility

The [manual release workflow](../../../../packages/syntrix/deployment/RELEASE.md)
produces `syntrix-VERSION.tar.gz`, including `meta.json`, Linux amd64/arm64 CLIs
and both canonical template trees, plus the versioned image
`ghcr.io/codetreker/syntrix-server:VERSION`. Current archive example values include
`VERSION@sha256:INDEXDIGEST`; the recorded index identifies both image platforms.
Console supplies its own managed values with the version tag only, such as
`ghcr.io/codetreker/syntrix-server:261013.1`, and `imagePullPolicy: IfNotPresent`.
The digest remains release validation and diagnostic evidence and is not appended
to Console's Pod image references. This delivery does not create a build on every
main commit: new instances consume the latest complete successfully published
release.

PR 1 introduces a compact integer `managed_runtime_contract: 1` in `meta.json`.
The version denotes the complete managed values/broker/readiness/initialization
contract defined here; it is not the release version or schema migration number.
Extend the existing `syntrix-cli` with a side-effect-free `deployment-contract`
command, rejecting positional arguments and emitting one bounded JSON object:

```json
{
  "managed_runtime_contract": 1,
  "version": "261013.10",
  "git_commit": "FULL_RELEASE_SOURCE_SHA",
  "modes": ["standalone", "distributed"],
  "render_phases": ["bootstrap", "acceptance", "full"]
}
```

Release builds inject the allocated version and full source commit into both
bundled CLIs using the same build identity. Packaging obtains/checks the bundled
native CLI's output and writes the marker into
metadata; it must fail on disagreement with release identity or required modes and
phases. This uses existing release tooling and dependencies. Add explicit
`--acceptance-only` to `render-kubernetes`, mapping to `Options.AcceptanceOnly`
and preserving `--bootstrap`/`--writes-quiesced` validation. The same release's
runtime image implements its declared initialization/status/finalizer/probe contract.
A local development CLI may identify itself as an unpublished development build;
Console requires the concrete selected release identity and never accepts it.

PR 3 selects published, non-draft, non-prerelease `syntrix-YYMMDD.sequence`
releases from the fixed administrative repository/workflow source, verifies the
metadata's successful exact workflow attempt/main source commit, and orders date
and sequence numerically. It validates the chosen package and bundled contract
before backend effects. Missing/unsupported markers, CLI disagreement, wrong
source/image identity or platform incompatibility fail visibly. Older published
packages without the marker remain operator artifacts; Console does not silently
fall back to an older compatible release.

Console chooses the CLI for its Linux host CPU, independently of cluster node
architecture. Its existing provisioning adapter owns bounded downloads, controlled
private extraction, immutable asset/hash cache verification and process execution.
Reject traversal/link escapes and enforce compressed/unpacked size, file-count
and path-length bounds. Invoke an absolute verified executable directly using a
bounded process context; no shell is involved. Arguments contain only fixed flags
and private file paths. Secret values and manifest output use protected files,
and subprocess failure output is sanitized before durable diagnostics. Do not
install a CLI globally or place credentials in command arguments.

Before allocation, PR 3 persists source repository/release/tag/asset identities,
computed archive SHA-256, version/source SHA, workflow attempt, image index digest
and platforms, resolved-at timestamp and contract version. Retry/recovery verifies
that exact receipt and cached/downloaded bytes. All bootstrap, acceptance,
finalizer and full-role execution use the recorded package and version tag with
`IfNotPresent`; ordinary start/restart and idempotent replay never discover another
version. Registry validation compares the selected tag's index digest/platforms
with metadata. The no-overwrite publication policy requires version tags never to
be repointed or overwritten; corrections allocate a new version. Existing release
tooling allocates fresh versions; this contract relies on the publication policy
without claiming GHCR-enforced tag immutability. Node cache reuse depends on that
policy, so a floating `:latest` is never rendered. PR 4 permits only explicit
supported compatible release revisions. The [lifecycle design](03.instance_lifecycle.md#published-runtime-package-selection)
owns latest-selection, durable source authority and package failure semantics.

PR 2 can reuse the public pure broker specification for supported contract
versions only. A package's managed contract change requires explicit Console
support before allocation; neither the marker nor matching template syntax is a
general adapter for arbitrary future runtime formats.

## Complete Broker Policy and Attachment

The specification has one owner and fixes supported semantics:

| Stream | Consumer |
|---|---|
| Explicit storage, replicas, positive max bytes/messages/age | Named durable pull consumer; filter `S.>` |
| Limits retention, DiscardOld, one consumer, acknowledgments enabled | AckExplicit, DeliverAll, ReplayInstant |
| No mirror/source/transform/republish; no destructive administrative flags | AckWait 30s, MaxDeliver -1, MaxWaiting 512, MaxAckPending 1000 |
| Required owner and revision metadata; no consumer idle limits | No BackOff or inactive deletion; inherit stream storage/replicas |

These consumer values make the documented SDK defaults explicit, preventing
allocation and runtime from choosing different inherited account settings.
[Pinned consumer configuration](https://github.com/nats-io/nats.go/blob/v1.48.0/jetstream/consumer_config.go#L140-L231)
describes those defaults. Limits retention retains acknowledged messages until
stream limits apply; bounded policy is therefore mandatory for managed instances.

Both objects carry `syntrix.installation_id`, `syntrix.instance_id`,
`syntrix.allocation_id`, and decimal `syntrix.spec_revision` metadata. Verify these
required keys exactly while tolerating unrelated/server metadata. Compare the
authoritative supported policy projection, canonicalizing documented server
normalization/inheritance. Do not compare entire SDK structs or overlook fields
that change delivery, cleanup, retention, or routing. The pinned SDK field inventory
is partitioned explicitly:

| Projection group | Required values or treatment |
|---|---|
| Stream routing/capacity | Name, singleton Subjects, Retention, Discard, Storage, Replicas, MaxConsumers=1, MaxMsgs, MaxBytes, MaxAge exactly match the specification |
| Additional stream limits | MaxMsgsPerSubject and MaxMsgSize unlimited, accepting documented 0/-1 normalization only; Duplicates=min(2m, MaxAge) |
| Unsupported stream behavior | DiscardNewPerSubject, NoAck, Sealed, DenyDelete, DenyPurge, AllowRollup, AllowDirect, MirrorDirect, AllowMsgTTL, AllowMsgCounter, AllowAtomicPublish, AllowMsgSchedules=false; SubjectDeleteMarkerTTL=0; Compression=none; default PersistMode |
| Stream external configuration | Placement, Mirror, Sources, SubjectTransform, RePublish absent; Template empty; ConsumerLimits inactive/ack-pending unset; nil/empty collections normalize equally |
| Consumer identity/delivery | Name=Durable=recorded name, one FilterSubject, no FilterSubjects, DeliverAll, AckExplicit, ReplayInstant, AckWait=30s, MaxDeliver=-1, MaxWaiting=512, MaxAckPending=1000 |
| Consumer content/lifetime | HeadersOnly=false, no BackOff, InactiveThreshold=0, MemoryStorage=false; resolved Replicas equals stream replicas |
| Other consumer behavior | OptStartSeq=0, OptStartTime absent, RateLimit=0, MaxRequestBatch/Expires/MaxBytes unlimited; no PauseUntil, priority/pinning/groups, DeliverSubject/Group, FlowControl or IdleHeartbeat |
| Informational/creation fields | Description and SampleFrequency may differ; FirstSeq is a creation parameter, not current delivery state; ignore returned message/ack sequence statistics; required metadata subset remains exact |

Use the pinned SDK default persistence mode's server representation and documented
consumer replica inheritance when normalizing; never normalize an enabled behavior
or positive extra cap to an absent value. Tests mutate every authoritative field
independently, including HeadersOnly and per-subject limits, and require rejection.
An SDK configuration-field change requires classifying it in this inventory before
upgrading the attachment policy.

Extend the existing pubsub factories with caller context:

```go
NewPublisher(ctx context.Context, opts PublisherOptions) (Publisher, error)
NewConsumer(ctx context.Context, opts ConsumerOptions) (Consumer, error)
Check(ctx context.Context) error // optional provider readiness capability
```

Managed providers lookup the exact stream/consumer and verify the complete spec.
Missing objects, ownership/revision mismatch, or incompatible policy fail with
sanitized typed errors. Neither publisher construction nor subscription creates,
updates, deletes, or repairs managed broker objects.

Operator providers lookup/verify, create missing objects using the same complete
spec, and refetch/verify after success, timeout, or concurrent AlreadyExists. They
never update conflicting objects. Remove both runtime CreateOrUpdate paths and
any second provisioning policy retained by direct factories. Cache only successful
attachments; failed/canceled resolution remains retryable and concurrent callers
retain their own deadlines. Every broker request uses its caller context.

`Check` fetches fresh object information; cached handles do not prove readiness.
Revision metadata is observable provenance, not compare-and-swap fencing. Names,
ownership, routing, storage, retention, and consumer semantics remain immutable;
PR 4 can reconcile permitted byte/count/age limits and revision through Console's
effect settlement rules. Old runtimes become unready on mismatch and cannot write
their old policy back.

Manager forwards publisher retry/storage and consumer durable/storage/buffer
options. Worker readiness requires both verified attachment and an active consume
loop. Observe terminal consume errors and `ConsumeContext.Closed()`; clear readiness
and propagate unexpected termination. Shutdown calls Stop, waits for Closed, then
closes its channel. Shared-account credentials provide routing separation with
account-wide authority; stronger per-instance broker authorization is outside the
accepted contract.

Current operator-generated settings effectively use MEMORY and durable `consumer`
because Manager drops configuration, despite module defaults saying file and
`trigger-delivery`. Updated example values declare policy explicitly. An existing
incompatible stream is rejected; this PR must not silently convert its storage,
rename its consumer, or rewrite its limits.

## Module-Owned Initialization and Cleanup Ordering

Storage/catalog and Identity retain schema/index ownership. Enumerate and deduplicate
every configured routed or split physical MongoDB database/collection, including
document, system, and revocation placements. Invoke the existing PostgreSQL schema
initializer and advisory-lock mechanism. Preserve administrator/default logical
database bootstrap ordering. Keep Scanner's lazy source-index ownership.

Separate required non-cleanup preparation from cleanup finalization:

```go
Prepare(ctx context.Context) (PreparationReceipt, error)
Inspect(ctx context.Context) (InitializationStatus, error)
Finalize(ctx context.Context, expected PreparationReceipt) (FinalizationReceipt, error)
```

The small initialization coordinator borrows configured physical Backends and asks
each owner for definitions; it does not duplicate SQL or index specifications.
Receipts contain a specification version/digest of physical placements and required
definitions, excluding credentials and documents. Preparation verifies PostgreSQL
schemas and non-cleanup indexes. Inspection reports preparing/prepared/finalized/
conflict from actual definitions. Finalization creates/verifies owner-defined
cleanup TTL, refetches every definition, and returns a complete observed receipt.
No additional runtime database table or stored finalized boolean is needed.

The owner inventory must explicitly distinguish `documents`, `sys`, and revocation
TTL. Preserve current deletion semantics: do not invent a new `sys` cleanup TTL
just because a system document contains expiry. Missing cleanup indexes remain
visible; incompatible keys/options are conflicts, not silently dropped/rebuilt.

Fresh managed bootstrap rejects an already-active document tombstone cleanup TTL.
Preparation never creates or toggles it. Operator maintenance retains its external
write/TTL pause requirements. A shared MongoDB server's global TTL monitor cannot
be disabled on behalf of one instance. Normal restarts inspect definitions and
never automatically recreate missing cleanup TTL.

A matching bounded `--inspect-initialization --output json` branch exposes the
observed preparation/status receipt without mutation. PR 3 obtains and records it
from the bootstrap container after its applied/flushed barrier, before handoff;
inspection alone does not certify bootstrap completion. The inspection and
finalization modes are mutually exclusive and share the same bounded physical
backend ownership.

Bootstrap automatically holds internal cleanup and Trigger writers, including
after its applied barrier. Normal read-path acceptance uses `AcceptanceOnly` in
the renderer and `--initialization-acceptance` in the runtime: suppress DeletionWorker
and Trigger evaluator/delivery starts while keeping required Puller/Indexer/Query/
Streamer/API read dependencies usable. Distributed renders additionally keep
writer-role replicas at zero. Role probes explicitly expose held roles as not
serving; the aggregate covers active read roles without claiming full normal health.
This small process option is necessary because standalone and Query colocate
writers/cleanup that replica controls alone cannot suspend. It adds no separate
controller, persistent authority, or runtime administrative HTTP endpoint.

After graceful bootstrap handoff, those read roles may become ready on prepared
data so the authenticated indexed-query acceptance can run. Keep external writers
and cleanup paused as well. Then invoke a bounded one-shot branch in the same image:

```text
syntrix --finalize-initialization --config-dir /etc/syntrix
        --expected-preparation <versioned-specification-digest>
        --indexed-query-accepted --initialization-timeout 30s --output json
```

The finite inspection/finalization branch runs before Manager composition, opens
only borrowed physical backend connections, finalizes/verifies the expected spec, emits one JSON receipt on
stdout, and closes its connections. Diagnostics go to stderr. It opens no Pebble
claims or listeners, performs no bootstrap/reset, and controls no global TTL switch.
The attestation records the caller's accepted-query prerequisite; the command
cannot independently prove an external query or Console lifecycle authority.

PR 3 invokes it in an observed normal-runtime container after accepted-revision,
role, and query checks, then persists the receipt. Operators invoke it after their
own query acceptance. Multiple index creations are not atomic: partial success or
response loss produces no completion claim; repeating the same expected spec
inspects/converges it idempotently. Console owns durable phase/attempt authority,
including finalizer effects, and must settle earlier finalization before deletion.
After the final receipt, apply the full normal render without acceptance hold,
observe all required role readiness, and complete external-path acceptance. Public
access/write release waits for those observations. Replacement of a state-owning
acceptance process follows the same settled-owner/drain rule as bootstrap handoff.
Restart does not repeat bootstrap or reset initialized data.

## Readiness and Process Ownership

Preserve GET/HEAD `/health` as liveness. Add exact GET/HEAD `/ready` returning
200 only for the enabled-role aggregate, otherwise 503, without credentials or
raw dependency errors. Both exact probe paths bypass application/auth budgets.
Unsupported methods and lookalike paths retain normal middleware behavior.

Register the existing dependency's standard `grpc.health.v1.Health`: empty service
name means enabled-role aggregate; `syntrix.liveness` is independent liveness;
role names are `syntrix.api`, `syntrix.query`, `syntrix.indexer`, `syntrix.puller`,
`syntrix.streamer`, `syntrix.trigger_evaluator`, and `syntrix.trigger_worker`.
Initialize NOT_SERVING explicitly before opening listeners. Remote dependencies
query their required role, avoiding aggregate readiness cycles for colocated `--all`.

| Role | Required evidence |
|---|---|
| Puller | Every configured source capture active after native idle batch, durable flush/checkpoint; buffer usable |
| Indexer | Valid persisted lineage/catalog, ordered applied/flushed ready barrier; required indexes not rebuilding/degraded |
| Query | Required Indexer role serving and initialized catalog/storage |
| Streamer | Its actual Puller ingestion subscription admitted; recoveries clear ready |
| Trigger Evaluator | Actual watcher admitted, initialized storage, verified broker/publisher |
| Trigger Worker | Identity/storage usable, broker exact spec verified, active consumer and delivery pool |
| API | Identity/catalog/storage usable, required Query/Streamer roles serving, realtime background ingestion active |

Disabled or explicitly held roles are excluded from the active process aggregate;
held roles remain NOT_SERVING individually and cannot satisfy full instance
acceptance. Initialization/client/channel construction alone is
insufficient. Owner modules publish synchronized snapshots/change notifications;
bounded dependency checks update them without blocking probe handlers. Module-owned
readiness configuration defaults to a 1s check interval and 2s timeout; validation
requires positive bounded values. A snapshot whose verification expires is unready,
so a stalled check cannot leave stale success. Transient loss clears ready, then
recovers through the existing owner mechanism. Fatal
asynchronous failure or unexpected return reaches Manager's terminal result and
the CLI; the process exits nonzero after owned shutdown. Track/drain every started
task, cancel before close, and preserve original causes through safe diagnostics.

Extend ordinary Puller subscriptions through the existing private subscribe and
SubscriptionDriver. An optional synchronized status handle reports state,
generation, cause, and change notification. Add `report_admission_ready` to the
existing SubscribeRequest and regenerate protobufs. It opts into admission
monitoring on the same event stream: extend PullerEvent with `admission_state`
(starting/replaying/admitted/recovering), `admission_generation`, and a sanitized
retryable/terminal reason category for failures. Reuse ready=true for admission after registration, source validation, requested replay, and live
admission. Emit ordered invalidation/recovering controls before same-stream source
loss or overflow recovery and a new admitted control after the next live barrier.
Existing `require_ready` retains Indexer's verified nonempty-boundary semantics.

An ordinary empty-source acknowledgment may have empty progress; it never creates
a checkpoint or advances reconnect progress. Streamer/Evaluator consume the ready
control after preceding events and require a matching admitted generation. Source/
transport loss clears readiness even if the retry channel remains open; overflow
recovery rearms admission. Terminal failure/closure reaches the module owner.
Admission controls are progress-neutral. Overflow stays in the existing driver and preserves its original
admission floors; reconnecting an empty-progress subscription at the current head
is not a valid overflow recovery.

The handle identifies both transport-attempt and admission generations; a stale
buffered ready control cannot restore an invalidated generation. Opt-in
subscriptions periodically refresh progress-neutral admission state on the existing
stream. The synchronized handle enforces a bounded freshness deadline
independently of the receive/dispatch goroutine, with a 1s refresh and 3s freshness
window. A blocked bounded event channel can delay subsequent status controls;
freshness expiry then clears readiness without dropping/reordering events, creating
an unbounded queue, or discarding admission history. Snapshot reads also check the
deadline. Serving recovers only with observed current admission controls and after
preceding business events have been consumed. Client-detected transport loss clears
immediately; remote source loss clears on its control, role-health observation,
or freshness expiry. A received control cannot authorize an older invalidated
transport/admission generation. Local and remote paths share those rules;
idle readiness requires no document write.

Template startup/readiness probes use HTTP `/ready` or role-specific gRPC health;
liveness uses `/health` or `syntrix.liveness`. Bootstrap probe readiness preserves
its applied/flushed barrier. Prepared runtime readiness, bootstrap completion,
cleanup finalization, Console accepted-revision Ready, and external access are
distinct observations. PR 3 supplies the latter product guarantees.

## Origins, Diagnostics, and Build Inputs

One validated exact scheme/host/port policy feeds REST CORS, classic WebSocket,
replica WebSocket, and SSE. Reject wildcard/invalid managed origins; preserve the
documented explicit operator development policy. Same-origin checks include port.
Protocol-specific absent/null Origin rules remain documented and tested. Do not
enable origins only in replica transport while leaving REST or classic WS divergent.

Sanitized errors retain `Unwrap` for local cause inspection, but emitted logs and
HTTP/CLI diagnostics never format credentialed NATS/Mongo/PG URLs, plaintext
configuration, rendered Secrets, passwords, or signing material. Include category,
subsystem, role, phase, and available installation/instance/allocation/spec revision.
Propagate owned contexts across subscriptions, broker calls, probes, and shutdown;
no new detached work uses context.Background as its operation owner.

For deployment verification, filter structured Pod logs by instance ID and role,
then compare `phase`, `spec_revision`, and failure category across preparation,
attachment, admission, and finalization. A concrete query is:

```bash
kubectl -n "$SYNTRIX_NAMESPACE" logs "$SYNTRIX_POD" --since=10m --all-containers |
  jq -c --arg id "$SYNTRIX_INSTANCE_ID" 'select(.instance_id == $id) |
    {role, phase, spec_revision, category, msg}'
```

The runtime uses its existing structured logging mode for this procedure; enable
that mode in the managed bundle and keep finalizer stdout machine-readable. Model
tool/API budgeting is inapplicable: no model-facing tool is introduced.

Allow public deployment Go/config and embedded template sources through the
current `.dockerignore` exclusion. Compile runtime and CLI in the Docker builder
to prove embed availability; final distroless contents remain the runtime binary.
Do not include deployment values, source credentials, or host sibling directories.
Prove reuse with a temporary external Go module using explicit require/replace and
`GOWORK=off`; defer actual Console broker-spec dependency wiring to PR 2 and
matched-package extraction/execution inputs to PR 3. Console's image must not
bundle an independent fixed runtime CLI/template copy. Release packaging compiles
both CLIs with matching identity, checks the native CLI's contract output against
metadata, and renders both modes/phases using that bundled CLI before publication.

## Execution and Acceptance Gates

Implement in dependency order within one worktree: public renderer/spec; provider
attachment and composition; owner-defined initialization/finalizer; subscription
admission and module readiness; process/probe/origin integration; CLI/package
compatibility marker and image/CI/release/docs.
Review the resulting change as one managed-runtime purpose, not unrelated cleanup.

| Gate | Required observations |
|---|---|
| Render/API | Both modes with bootstrap/acceptance/full renders; embedded/explicit equivalence; customized names/resources/shared keys; managed version-tag image and IfNotPresent without digest/latest; external-module build; strict values rejection; atomic 0600 output and secret-safe failures |
| Broker | Two instances on one account route only their tasks; same-instance Workers share durable; startup preserves full policy/metadata; missing/foreign/conflicting objects reject; operator races/response loss verify exact spec |
| Initialization | Routed/split placements; concurrent schema initialization; idle bootstrap; no premature document TTL; internal/external writer hold; accepted-query finalization and full activation; wrong digest/partial finalization/restart inspection; no Manager/listener/Pebble opened by finalizer |
