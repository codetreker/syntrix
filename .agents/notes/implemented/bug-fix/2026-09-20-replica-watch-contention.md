# Agent Note: 副本查询视图竞争与 watch 活性

Status: implemented

## Problem

复制会更新发送阶段、分页和轮次等控制字段。将整个 manifest revision 作为查询视图
身份，会让这些变化触发无意义的全量重建。重建次数用尽后终止 watch，使正常复制
永久停止本地结果更新；多次废弃扫描的累计成本也可能被误判为单个结果集超限。

## Decision

[查询与 watch](../architecture/2026-09-18-sdk-replica-query-watch.md)保留原有业务语义、
资源上限和所有权；本决定细化查询视图及竞争处理，不修改存储格式或复制 checkpoint。

| 内容 | 行为与原因 |
|---|---|
| 查询视图 | 从活动 physical epoch、source generation、dirty target 与 issue 的保护 ID 并集派生身份，保留同代保护变化的可见性语义 |
| 普通控制更新 | 查询收到通知后核对派生身份；发送阶段、分页或轮次变化不单独触发重建，原始 manifest 通知仍提供给同步与状态消费者 |
| 派生成本 | 按原始 revision 缓存有界的最新 hash，临时排序和编码纳入读取预算；身份、生命周期及定义校验不能因缓存命中而省略 |
| 扫描硬上限 | 同一目标视图跨分页累计候选及编码字节；稳定结果本身超限仍终止 |
| 累计工作额度 | 废弃尝试和重复增量处理只消耗本轮工作额度；额度用尽时让出队列，不能把重复扫描算成更大的结果集 |
| 长 watch | 竞争后保留观察者与最后成功结果；25ms 起、200ms 封顶退让，稳定后继续更新 |
| 单次读取 | get/getPage 仍以有界错误结束持续竞争；不能连带注销共享查询的 watch |
| 取消与失败 | 最后观察者退出或 owner 失效时取消等待；真实资源/存储错误仍终止对应查询并保留错误 |

每个规范化查询最多一个运行任务和一个退让 timer，等待期间不占共享执行队列。
`query` 的 `contended` / `recovered` 诊断按一次竞争 episode 关联，不记录查询条件、
业务 ID 或 payload。应用诊断回调导致的关闭仍需遵守原有回调隔离。

## Alternatives

**增加重建次数。** 只能推迟终止；持续的无关控制变化仍会扫描、消耗预算并最终退出。

**只让 watch 重试。** 可以保留订阅，但无关控制字段持续变化仍可能让它长期无法发布。
派生可见性身份消除这类错误失效，真实视图竞争再执行有界退让。

**仅比较 generation/epoch。** 会漏掉同 generation 内恢复保护 ID 的增减。保护 ID 并集
必须参与视图身份；文档、成员及 assumed metadata 仍由行变更触发重算。

**新增持久化查询版本。** 需要修改所有相关写路径和持久化契约。现有 manifest 字段
已足以派生所需身份，保留原始数据格式能避免额外的维护责任。

## Consequences

- 正常复制控制活动不再永久停止 watch；真实视图持续竞争时仍可能暂时没有新结果，
  不承诺固定墙钟延迟。
- 新旧索引及最后成功结果继续共享资源账本，退让不能放宽候选、保留内存或输出限制。
- 查询状态与复制进度分离；恢复 watch 不表示所有上行工作已被远端确认。
- 现有记录、pending、pin 和 checkpoint 不因查询竞争被丢弃或重写。
